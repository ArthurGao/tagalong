# TagAlong UI 风格指南

TagAlong 只有一个 Next.js 应用，但分成三个 **surface（界面区域）**，每个区域有独立的视觉风格：

| Surface | 用户 | 场景 | 风格概念 |
|---|---|---|---|
| `public` | 买家 | 手机上从群里点开链接，30 秒内决定买不买 | **集市报名单 (Market sign-up sheet)** |
| `merchant` | 商家 | 一边备货 / 上课，一边用手机管理订单、核销取货 | **摊主账本 (Stall ledger)** |
| `admin` | 平台运营 | 在桌面电脑上审查商家、处理争议、下架接龙 | **控制室 (Control room)** |

三个区域共享**同一套组件骨架**（shadcn/ui 组件、lib、API client），但颜色、字体、圆角、信息密度完全由 surface 的 CSS 变量决定。

---

## 1. 实现机制

1. **每个路由组的 layout 设置自己的 surface 和字体：**
   ```tsx
   // app/[locale]/(public)/layout.tsx
   <div data-surface="public" className={`${bricolage.variable} ${figtree.variable}`}>{children}</div>
   // app/[locale]/dashboard/layout.tsx  → data-surface="merchant", Atkinson Hyperlegible
   // app/[locale]/admin/layout.tsx      → data-surface="admin" className="dark", IBM Plex Sans + Plex Mono
   ```
   字体通过 `next/font/google` 加载，且只在对应的 layout 中引入。这样买家页面不会下载后台用的字体。

2. **在 `globals.css` 中按 surface 定义 shadcn 变量：**
   ```css
   [data-surface="public"]   { --background: ...; --primary: ...; --radius: 14px; --font-display: var(--font-bricolage); ... }
   [data-surface="merchant"] { ...; --radius: 8px; }
   [data-surface="admin"]    { ...; --radius: 4px; }
   ```
   Tailwind 的 `bg-background`、`text-primary`、`rounded-[var(--radius)]` 等都映射到这些变量。同一个 `<Button>` 组件放在三个区域里，会自动呈现三种外观。

3. **目录隔离：** 业务组件分别放在 `components/public/`、`components/merchant/`、`components/admin/`，不同区域之间**禁止互相 import**，只能共享 `components/ui/` 和 `lib/`。

4. **中文字体：** 三个区域都不加载网络中文字体（文件太大），统一在西文字体后面接系统字体栈：
   ```
   "PingFang SC", "Hiragino Sans GB", "Noto Sans SC", "Microsoft YaHei", sans-serif
   ```

5. **暗色模式：**
   - `public`：只做浅色。商品照片和分享出去的截图需要保持一致的观感。
   - `merchant`：浅色为默认，跟随系统设置切换暗色。
   - `admin`：只做暗色。这样运营人员一眼就能分清自己在 admin 还是商家后台。

## 2. Public：集市报名单

**设计思路**：微信接龙之所以有用，是因为「#1 张三 #2 李四…」这份不断变长的名单本身就是最有力的社交证明。所以页面的主角就是这份**报名单**，而不是一张营销海报。视觉上参考农贸集市摊位上的手写报名纸：清爽、带编号、能直观看到「还剩几个位置」。

### Tokens

| 名称 | 值 | 用途 |
|---|---|---|
| Leaf mist | `#F2F5EF` | 页面背景，带一点绿调的冷白（刻意避开米色） |
| Paper | `#FFFFFF` | 报名单、表单的底色 |
| Bush ink | `#1A2B22` | 正文，深林绿黑 |
| Pōhutukawa | `#C92A39` | 主按钮「接龙」、进度条，**整页唯一的强调色** |
| Kōwhai | `#F3C534` | 「剩 3 份」紧缺提示的底色，只在库存紧张时出现 |
| Rule | `#D3DCCF` | 报名单的横线、分隔线 |

- **字体**：
  - 标题、价格、接龙序号用 **Bricolage Grotesque**（600–800），数字使用 `tabular-nums`
  - 正文用 **Figtree**（400/500）
- **字号**：基准 17px（手机），比例约 1.25；价格 32px，接龙序号 22px。
- **圆角**：14px，只用在主要容器上；列表行本身不加圆角。

### 布局（手机端，内容最大宽度 480px，左对齐）

```
┌──────────────────────────┐
│ [商品图 4:3，可滑动]       │
│ 车厘子 2kg 接龙            │  ← Bricolage 28px
│ 小林的果园 · Albany 自提    │
│ ████████████░░░  23 / 30  │  ← 进度条，Pōhutukawa 色
│ 周六 10–12 点取 | 剩 2 天   │
├──────────────────────────┤
│ 选规格  [2kg $39] [5kg $89]│
├──────────────────────────┤
│ 已接龙                     │
│ #23  Arthur G.   2kg ×1   │  ← 报名单，带横线
│ #22  高*         5kg ×1   │
│ #21  匿名        2kg ×2   │
│      查看全部 23 人         │
├──────────────────────────┤
│ 详情 / 取货 / 退款政策      │
└──────────────────────────┘
┃ $39            [ 接龙 ]  ┃  ← 底部吸附栏，始终可见
```

### 原则

- **唯一的强调色**：Pōhutukawa 红只用在「接龙」按钮和进度条上，其他地方都不用。
- **最新的人排最前**：报名单的最新一行在顶部；付款成功回到页面时，自己的那一行会有一次短暂的高亮。这是整页**唯一**的动效，必须遵循 `prefers-reduced-motion`。
- **不做营销腔**：不放 hero 横幅，不写「限时抢购！」之类的标语，文案只陈述事实（价格、时间、地点、剩余数量）。
- **免费报名**：
  - 价格位置显示「免费」，与付费价格使用同样的字号和字重，不要做成小标签
  - 按钮文字为「报名」，报名单标题为「已报名」
  - 其余视觉保持一致，不另起一套样式
- **自定义报名字段**：在买家信息下方顺序排列，与基础字段同样式，不用卡片或分组框包起来
- **售罄状态**：按钮变为「已接满」并置灰，同时报名单保持可见。名单本身就是证明，下次开团时会有回头客。

## 3. Merchant：摊主账本

**设计思路**：商家最常做的事情是「看今天有谁要来取货，然后一个个勾掉」。所以整个后台的核心交互是一份**可以逐行勾选的账本**，而不是一堆数据卡片。界面整体安静、清晰，适合在嘈杂的环境下单手操作。它和 public 共享同一种深绿墨色，让人感觉是同一个品牌，但不使用 public 那种热烈的红色。

### Tokens

| 名称 | 值 | 用途 |
|---|---|---|
| Shelf | `#F1F2EE` | 页面背景 |
| Paper | `#FFFFFF` | 列表和面板的底色 |
| Bush ink | `#1A2B22` | 正文（与 public 相同，保持品牌连续性） |
| Fern | `#1F6B4A` | 主操作按钮（发布、核销） |
| Status: paid | `#2A5DB0` | 已付款 |
| Status: pending | `#A86A12` | 待付款 |
| Status: done | `#1F6B4A` + ✓ | 已取货 / 已上课 |
| Status: refunded | `#6B7268` | 已退款 |
| Status: confirmed | `#2A5DB0` | 已报名（免费），与 paid 同色，文字不同 |
| Status: no-show | `#6B7268` + ⊘ | 未到 |
| Danger | `#B42318` | 退款、取消接龙，只用于破坏性操作 |

- **字体**：全部使用 **Atkinson Hyperlegible**（400/700）。这款字体专为易读性设计，能清楚区分 0/O、1/l，核对订单号和手机号时不容易看错。数字使用 `tabular-nums`。
- **字号**：基准 16px，信息密度中等，行高 1.5。
- **圆角**：8px。
- **状态表达**：不能只靠颜色区分，每个状态都要同时带文字标签或图标，方便色弱用户。

### 布局

```
手机端：底部 3 个 tab —— 接龙 | 订单 | 我的
桌面端（≥1024px）：左侧 220px 侧边栏，右侧内容区

订单页（核心）：
┌────────────────────────────┐
│ 车厘子 2kg 接龙   [分享文案]  │
│ [待取货 18] [已取货 5] [全部] │  ← 筛选
│ 🔍 搜名字 / 订单号 / 手机尾号  │
├────────────────────────────┤
│ #23 Arthur Gao   2kg×1  [✓] │  ← 整行都可点；点击后弹出确认
│ #22 高阳          5kg×1  [✓] │
│ #21 Lily Chen    2kg×2  ✓已取│
└────────────────────────────┘
```

### 原则

- **列表优于卡片**：订单和接龙都用列表行展示，不做卡片网格。
- **核销优先**：「核销」是最大、最容易点到的操作。核销后显示 5 秒「撤销」toast，不需要二次确认弹窗。
- **退款要谨慎**：退款操作放在订单详情的抽屉里，弹窗中必须显示退款金额，按钮上写明「退款 $39.00」。
- **空状态就是引导**：比如还没有接龙时，直接显示「发布第一条接龙」按钮。

## 4. Admin：控制室

**设计思路**：运营人员的工作是查询、比对和处置风险。界面应该高密度、桌面优先，并且始终提醒「你正在操作生产数据」。admin 只做暗色，这样永远不会和商家后台搞混。

### Tokens

| 名称 | 值 | 用途 |
|---|---|---|
| Slate deep | `#1A1F26` | 页面背景，带蓝调的石板色，不用纯黑 |
| Slate panel | `#232A33` | 表格和抽屉的底色 |
| Line | `#323B46` | 表格分隔线 |
| Text | `#E2E7EC` | 正文 |
| Muted | `#93A0AD` | 次要信息 |
| Signal amber | `#E5A23A` | 风险标记（新商家、高退款率、争议） |
| Danger | `#E5484D` | 停用、下架；以及生产环境的顶部横幅 |
| Link | `#7AAEF2` | 链接 |

- **字体**：
  - 界面文字用 **IBM Plex Sans**（400/500/600）
  - 订单号、Stripe ID、金额等需要复制核对的数据用 **IBM Plex Mono**（等宽字体便于对齐和比对）
- **字号**：基准 14px，表格行高 36px，属于高密度布局。
- **圆角**：4px。

### 布局（桌面优先，最小宽度 1280px，手机端只保证能浏览、不变形）

```
┌ PRODUCTION ─────────────────────────────────────────────┐ ← 生产环境红色横幅（staging 用琥珀色）
│ 侧栏      │ 商家  [状态 ▾] [风险 ▾] 🔍                   │
│ 概览      │ ─────────────────────────────────────────── │
│ 商家      │ slug      名称     状态    GMV    争议  创建  │
│ 接龙      │ xiaolin   小林果园  ACTIVE  $2.1k  0    3d   │
│ 订单      │ ⚠ abc12   ...      ACTIVE  $9.8k  2    1d   │ ← 风险行左侧显示琥珀色条
│ 争议      │                                ┌──────────┐ │
│ 审计日志  │                                │ 右侧详情抽屉│ │
└──────────────────────────────────────────────────────────┘
```

### 原则

- **点行即看详情**：点击表格行打开右侧抽屉，不跳转页面，保留列表上下文。
- **破坏性操作要留痕**：停用、下架这类操作必须填写原因，并且需要手动输入商家 slug 确认。所有操作都写入审计日志，并在页面上可见。
- **PII 默认遮罩**：买家的邮箱和手机号默认遮罩显示，点「显示」后才展开，且这次查看动作本身也会记入审计日志。
- **不做装饰**：不画图表装饰；概览页只放 4 个数字和一个「待处理」列表。

## 5. 三个区域共享的规则

- 正文对比度达到 WCAG AA；所有可交互元素都有可见的 `:focus-visible` 样式。
- 文案使用简洁的句子，按钮写明具体动作（「发布接龙」→ toast 显示「已发布」）；错误信息要说清楚怎么解决，不道歉。
- 避免以下模板化特征：每个标题上方的全大写小标签、所有区块的淡入上滑动画、千篇一律的圆角卡片阴影、在按钮文字后面加「→」。
- 金额一律用 `formatCents()` 格式化，时间一律用 `Pacific/Auckland` 时区显示。
